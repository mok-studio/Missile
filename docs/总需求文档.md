### 本工作区（GitHub 克隆）的构建方式 —— **没有 Maven**

```powershell
# JDK 21 不在 PATH 里时用绝对路径；jar 缓存直接用 ~/.m2/repository
$javac = 'C:\Program Files\Java\jdk-21\bin\javac.exe'
$jars  = (Get-ChildItem "$env:USERPROFILE\.m2\repository" -Recurse -File -Filter *.jar).FullName -join ';'
$src   = (Get-ChildItem -Recurse -File src\main\java -Filter *.java).FullName
& $javac --release 21 -encoding UTF-8 -nowarn -proc:none -d build-check -cp $jars $src
# EXIT=0 即"编译通过"（等价于 mvn package 的编译阶段；打 jar 需自行 jar cf）
```

- ⚠ `javac` 只认 `--release`（**双横线**），写 `-release` 会报"无效的标记"。
- ⚠ **不要往 `target/` 里写东西**：该目录在本工作区被沙箱拒绝（`Access denied`），输出目录用工作区根下的新建目录（如 `build-check`），验证完删掉。

派生判定：`beamRiding()` = 仅 SEMI_LOS；`radarHoming()` = ACTIVE 或 SUPER_ACTIVE（比例导引打提前量 + 惯性记忆 + 自主重截获；**同时是 RWR 的威胁来源**）；`decoyChance() <= 0` 时 `Missile#checkDecoy` 直接返回（免疫干扰）。

### 2.2 导引头与发射流程（`SeekerListener`）

1. 手持 TNT 右键 → 开启导引头（`player.hasPermission("missile.use")` 且个人开关与全服开关都开启）。
2. `refresh()` 每 2 tick 刷新一次锁定：`LOCK_RANGE = 128` 格、`LOCK_CONE = 10°` 锥角、要求视线可达，候选经 `TargetFilter.canTarget` 过滤，排除盔甲架。
3. 再右键发射：`MUZZLE_OFFSET = 1.2` 格出膛偏移，扣 1 个 TNT。
4. `MissileManager.MAX_ACTIVE = 64`，超限拒绝发射。

### 2.3 导弹实体与外形（`Missile`）

- 物理弹体：`SmallFireball`（`setYield(0)`、非引燃；取消 `ProjectileHitEvent` 自行结算爆炸）。
- 外形：**`BlockDisplay` 展示 `Material.END_ROD`（末地烛方块模型）**，每 tick 同步到弹体位置；`Transform` 由 `model.*` 配置驱动（缩放/平移/朝向）；`align-to-flight: true` 时用轴角转四元数把方块 +Y 轴对齐飞行方向（已实测 8 方向误差 0）；朝向变化 <≈2° 时不重发变换元数据包。
- 尾焰 + 尾烟粒子每 tick 生成（`flameParticle` / `smokeParticle`），`particle-range` 内无观察者则跳过。
- 近炸引信 `PROXIMITY_FUSE = 3.0` 格；脱锁惯性记忆；干扰判定（`checkDecoy`）。

### 2.4 目标筛选（`TargetFilter` + `FilterStorage`）

**白名单模型**（每玩家一份）：`enabled`（模式开关）+ `entity` 类（`entityTypeIncluded`「任意生物」+ 实体 ID 白名单）+ `player` 类（`playerTypeIncluded` + 玩家白名单；名单为空 = 允许所有玩家，非空 = **只允许名单内玩家**）。

```
/msl filter entity [set|add|clear] [<实体ID...>]     # zombie 或 minecraft:zombie 均可
/msl filter player [set|add|clear] [<玩家名...>]     # 只接受当前在线名字，同时记录 UUID + 名字
/msl filter clear                                   # 清空全部筛选数据（不动 on/off）
/msl filter on | off                                # 启用 / 停用筛选模式（off = 自由锁定）
/msl filter list                                    # 只读查看
```

- `set` = **先清空全部**筛选数据再写入本次类型与 ID；`add` 与"直接跟 ID"都是追加；`set`/`add` 缺后续必选 ID → 该 `set`/`add` 整体无效（不清空、不写入）。
- 成功写入类型或 ID 会自动把模式置为 `on`。
- `minecraft:player` 不能作为实体 ID（有专门报错）。
- 持久化：**JSON 默认**（`plugins/Missile/data/filters.json`，Gson 美化输出）、**MySQL 可选**（仅用 JDK `java.sql`，自动建表 7 列 `utf8mb4`）；检测不到 `com.mysql.cj.jdbc.Driver` 或连接失败 → **告警并自动回退 JSON**（本次运行内不再重试）。
- 异步模型：主线程打快照成不可变 `Row` → 异步写盘/写库；每 `auto-save-interval-seconds`（默认 5s）脏检查，内容变了才写；关服 `stop()` 同步兜底落盘；载入回主线程写入，**本地已改过的玩家以本地为准**。

### 2.5 命令与权限

```
/msl                                       → 状态
/msl status                                → 状态（型号 + 导引头 + 个人开关 + 全服开关 + 筛选模式 + 用法）
/msl ir [default|player|entity] [usefilter|filteroff]   → 模式与白名单通道**相互独立**；关闭要显式写 filteroff（见 §7 决策 14）
/msl semi | active | semiLOS               → 仅切换型号（无附加参数）
/msl super_active default                  → 任意目标 + 清空 safilter
/msl super_active entity|player [set|add|remove|clear] [值...]   → 1.0.3：按类编辑 safilter（裸值 = add）
/msl super_active filter <list|clear>      → 查看 / 清空 safilter
/msl filter <entity|player|clear|on|off|list> [set|add|remove|clear] [...]   → 1.0.3 新增 remove
/msl on | off                              → 个人开关
/msl default                               → 1.0.3：把自己的全部导弹设置恢复默认（保留型号与 on/off）
/msl global <on|off>                       → 全服开关
/msl reload                                → 热重载
```

| 权限节点 | 默认 | 覆盖命令 |
|---|---|---|
| `missile.use` | `true` | `/msl <型号>`、`/msl filter ...`、`/msl on|off`、`/msl default`、`/msl status` |
| `missile.admin` | `op` | `/msl super_active`（含参数）、`/msl global on|off`、`/msl reload` |

- **`plugin.yml` 故意不给命令声明 `permission:`**，权限由 `MissileCommand` 按子命令校验；否则只带 `missile.admin` 的管理员会被 `missile.use` 挡住。
- 原 `missile.superactive` 已**删除并改名**为 `missile.admin`（破坏性变更，服务器需在 LuckPerms 补授）。
- **参数容错（全局规则）**：从左往右解析，遇第一个非法参数即停止，**只执行非法参数之前的部分**。例 `/msl super_active player 114514` ≡ `/msl super_active player`；`/msl ir 114514` ≡ `/msl ir`（不改变模式）。被忽略部分静默处理。
  - **`remove` 的例外（1.0.3）**：`filter … remove` 与 `super_active … remove` 遇到"**合法但名单里没有**"的条目只在回执里列出来、**不中断**；遇到**非法**输入（未知实体 ID / 找不到的玩家）仍按上面的规则中断。
- **Tab 补全**：按位置给出全集并按权限过滤（位置 1 型号/on/off/filter/status/**default** + admin 的 super_active/global/reload；位置 2 按类型给模式或 `set|add|remove|clear|list` 或 on/off；位置 3 `set|add|remove|clear` / `usefilter`；**`super_active` 的 entity/player 之后先给 4 个动词再给全部实体 ID / 在线玩家名**；位置 4 `set`/`add` 给全集、**`remove` 给名单里已有的条目**）。

### 2.6 开关

- 个人开关 `/msl on|off`：静态 `Map<UUID,Boolean>`，**仅内存**；未记录 = 默认开启。
- 全服开关 `/msl global on|off`：静态 `globalEnabled`，启动初值取 `config.yml` 的 `missile.global-enabled`，运行期**仅内存**（不回写 config，避免抹掉注释）。
- 两者**相互独立**，都开启时该玩家才可用导弹。全服关闭时 `refresh()` 会清空所有导引头并放行原版 TNT。

### 2.7 RWR（雷达告警接收器）+ MAWS（导弹逼近告警接收机）—— ✅ 已按新需求重写（见 §3.6 / §3.7）

`RwrManager` + `RwrListener` + `RwrDisplay`；每 tick 轮询导弹/导引头状态（无 hook）。

- **开机条件（RWR 与 MAWS 完全相同，三条全满足）**：
  ① 权限 `missile.use` **或** `missile.admin`（用户补充：admin 默认拥有所有权限，无需再单独授予 use）；
  ② 自己用 `/msl on` 开了导弹模式（**每 tick** 判，`/msl off` 立即静默）；
  ③ 背包含指南针 `minecraft:compass`（与权限一起每 5 tick 复查缓存）。
- **RWR**（黄/红 BossBar，8 方位箭头 `rwr.dir-0..7`）：威胁来源 = `radarHoming()`（ACTIVE / SUPER_ACTIVE）与 `SEMI_ACTIVE`；告警音间隔敌跟踪 **0.2s（4 tick）**、敌导弹 **0.1s（2 tick）**。
- **MAWS**（红色 BossBar，文本 `&c⚠ MAWS: %msl_maws%`）：**任何**在飞导弹（不限型号）进入 **40 格**内即告警，`%msl_maws%` 替换为方向箭头；与 RWR **并存**（`RwrDisplay` 按 `Slot.RWR` / `Slot.MAWS` 两条独立 BossBar，不会互相顶掉）。
- 全部可调项在 `msl_config.yml` 的 `rwr:` 与 `maws:` 板块。

### 2.8 文案与颜色（i18n）

- 来源优先级：`config.yml` 的 `messages:` 覆盖 → `lang/<language>.yml` → 返回 key 本身（并在控制台告警一次）。
- `messages:` 支持**嵌套**（`command: { enabled: … }`）与**扁平**（`"command.enabled": "…"`）两种写法（后者靠 `getValues(false)` 取字面键名，已修复此前的静默失效）。
- 颜色：`&` 代码（`&6 &c &l &r` 等）+ 十六进制 `&#RRGGBB` **和**原版写法 `&x&R&R&G&G&B&B`，统一展开成 `§x§R§R§G§G§B§B`（`Lang.colorize` 公开方法，已实测）。
- 语言文件释放到 `plugins/Missile/lang/`；`config.yml` 的 `language` 选语言（内置 `zh_cn` / `en_us`）。
- 规则：**所有面向玩家的文本必须走 `Lang.get()` / `Lang.msg()`，禁止硬编码**（控制台诊断日志除外）；新增文案必须**同时**改 `zh_cn.yml` 与 `en_us.yml`，两边 key 数量必须一致。

### 2.9 配置文件板块（**两份文件**）

| 文件 | 内容 | 被谁读 |
|---|---|---|
| `plugins/Missile/config.yml`（50 行） | **通用项**：`language` / `messages`（按 key 覆盖文案）/ `filter.storage`（type、保存周期、json 路径、MySQL 七项） | Bukkit `getConfig()` |
| `plugins/Missile/msl_config.yml`（290 行） | **导弹参数**：`missile.global-enabled` / `launcher`（导引头 5 项）/ `flight`（飞行 6 项）/ `beam`（驾束 2 项）/ `particles`（粒子 15 项）/ `model`（模型 11 项）/ `explosion` / `types`（5 型号 × 13 项）/ `rwr`（10 项）/ `maws`（4 项） | `Settings.loadMissileConfig()` 自己加载 |

- `msl_config.yml` **不是** Bukkit 的 `getConfig()`：`Settings` 自己 `YamlConfiguration.loadConfiguration(file)`，文件不存在时先 `plugin.saveResource(...)` 从 jar 释放（与 `Lang` 释放语言文件同一套路）。
- 两份文件都由 `Settings.load(plugin)` 读取；`/msl reload` 会同时重读，**不必重启**。
- 删掉 `msl_config.yml` 里任意一行 = 该项回落到内置默认值，不报错（有测试覆盖，见 §9 `GameplayCheck`）。

### 2.10 健壮性约定

`MissilePlugin.onEnable` 按阶段 `try/catch (Throwable)`，失败只记 `SEVERE`（含完整堆栈）不向外抛，核心组件为 null 时提前 `return`（不注册命令与主任务）；`Settings.load()` 只重读文件、无副作用，可重复调用（`/msl reload` 直接再调）。
